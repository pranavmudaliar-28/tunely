# Decisions

Choices made while building, newest last.

- **TypeScript 6.0.3, not 7.x.** TS 7 (native port) is the latest release, but typescript-eslint 8.72 supports only `<6.1.0` and needs the TS compiler API. Revisit when typescript-eslint supports 7.
- **Internal packages ship TypeScript source.** `@tunely/shared` and `@tunely/db` export `src/index.ts`. Next.js transpiles them (`transpilePackages`); the API and worker run with `tsx` in dev and are bundled with esbuild for production, so no per-package build step or watch process is needed.
- **`moduleResolution: Bundler` everywhere.** Every runtime path goes through a bundler or tsx, so extensionless imports work and Next/Turbopack resolves them the same way.
- **pnpm installed with `npm i -g pnpm`.** `corepack enable` fails without admin rights on Windows (EPERM in Program Files).
- **Postgres on host port 5433 locally.** 5432 is often taken by other projects; override with `POSTGRES_PORT`.
- **Sync upserts only rows whose values changed** (`ON CONFLICT … DO UPDATE … WHERE row IS DISTINCT FROM excluded`), so a re-run writes nothing. Channels that leave iptv-org, become blocklisted or NSFW are deleted with their feeds, streams, logos, health and curation rows, except `hidden` and `removed` curation rows, which stay so a takedown survives the channel returning.
- **Streams with `channel: null` are skipped.** About 1,900 iptv-org streams aren't mapped to a channel, so they can't be curated or shown.
- **`stream_checks` is range-partitioned by month** in hand-edited SQL (Drizzle can't express partitions). A `DEFAULT` partition catches stray rows; `ensure_stream_checks_partition(ts)` creates monthly partitions.
- **Admin endpoints use a single bearer `ADMIN_TOKEN` until Phase 5.** The value `change-me` is treated as unset, so admin is closed by default.
- **Curation via `curate` CLI until the admin UI exists.**
- **NAT64-aware SSRF check.** On DNS64 networks public IPv4 hosts resolve to `64:ff9b::/96`; the fetcher judges the embedded IPv4 address instead of refusing the whole range. Before this fix 3,155 streams were wrongly marked `blocked_ip`.
- **Segment check reads the first 32 KB** of one segment (cap 5 MB), enough to prove it's served without downloading video at scale.
- **Hand-rolled m3u8 parsing** (~40 lines) instead of `m3u8-parser`: we only need variants, resolution and one segment URI.
- **Score** = 80 × recency-weighted check success + 20 for a fast manifest, blended 60/40 with player reports once there are ≥ 5 in 24 h; a failed latest check caps it at 40 (below the public threshold of 50). See `apps/worker/src/health/score.ts`.
- **Playback reports go through a Redis list** (`playback-reports:buffer`, capped at 100k) and the worker flushes them every 10 s in batches; simpler than one BullMQ job per report.
- **Rate-limit keys use a hash of the client IP**, held in Redis only for the 1-minute window. Fastify request logs omit IPs and user agents.
- **Takedown endpoint moved to Phase 5** with its Turnstile form.
- **Each package tests against its own database** (`<TEST_DATABASE_URL>_api`, `_worker`), created and migrated by a vitest global setup, so turbo runs them in parallel.
- **Measured (local, 2026-10-28):** full catalog sync 40 s; full health check of 16,031 streams ≈ 25 min at concurrency 100; 50-stream browser sample in Chrome: 45/50 played (90%); cached API p95 4–7 ms, cold first page up to ~470 ms.
- **Logos are plain `<img loading=lazy referrerpolicy=no-referrer>` from the iptv-org URLs**, not `next/image`: logos live on hundreds of hosts, and allowing them all would turn the Next image optimizer into an open fetch proxy. Downside: some source logos are 300–800 KB PNGs. **Measured Lighthouse mobile (prod build, 2026-10-28): accessibility 100 on home/watch/browse; performance 61 home, 66 watch, 85 browse with third-party logos, 90 home with them blocked.** The guide's logo-cache job (resize to WebP, serve from our CDN) closes the gap; it needs `sharp` and object storage, pending approval.
- **Native `<dialog>` for the Ctrl/⌘K palette and native `<select>` for filters and quality** instead of shadcn/Radix components: same accessibility (focus trap, Esc, D-pad friendly) with no extra JS. shadcn is initialised (`components.json`, `cn`) for when we need richer components.
- **Inline SVG icons from the canvas** instead of `lucide-react`.
- **The player stays mounted across channel changes** (so fullscreen survives channel up/down) and destroys the hls.js instance in the attach effect's cleanup on every stream or channel change. A failing stream falls through to the channel's next web-playable stream before any error is shown.
- **Channel up/down walks the list the viewer came from** (rail, grid, search, favorites), stored in sessionStorage; falls back to related channels.
- **Home rails use India as the default country** until per-user settings (Phase 5). Sort-by ("Most watched", "Best quality") from the Browse design is not built yet; lists are A–Z.
- **The theme script is the only `dangerouslySetInnerHTML`**; it is static, and Phase 6's CSP must allow it by hash.
- **E2E (`pnpm --filter @tunely/web e2e`) runs against a live local stack** using installed Chrome; it is not in CI yet because CI has no seeded catalog. No synthetic test stream: ffmpeg isn't available here to make one.
- **Directory mode (owner decision, 2026-10-28), replacing "only approved, playable channels are public".** All 30,900 channels are listed with a status: live 4,144 · offline 6,084 (streams exist, none play) · no stream 19,294 · closed 1,378. Live first everywhere; dead cards are greyed with a label, and their watch page explains why (no stream / closed / offline / browser-only) with "Try next channel". Kept out regardless: NSFW and the iptv-org blocklist (797 channels, iptv-org's own takedown list), plus anything a curator hides or removes. Home rails, trending, related channels, channel up/down and the sitemap use live channels only; dead watch pages are `noindex`. Trade-off accepted by the owner: most listed channels can't be watched, and pay-TV channels now appear in the directory (they play only if a stream passes the health check).
- **`public_channels` is a materialized view** (status needs a lateral join over every channel): refreshed concurrently after each sync, health batch, hourly scoring and curate command. Uncached list queries stay fast with indexes on (status_rank, name, id).
- **API cache keys carry a version** (`api:<CACHE_VERSION>:…`), bumped when a response shape changes, so old cached JSON can't break clients after a deploy.
- **Search ranks names that start with the query first, even dead ones**, then live before dead, then fuzzy matches.
- **API listens on `::` (dual-stack).** With `0.0.0.0`, `localhost` on Windows tried IPv6 first and every request paid ~200 ms.
- **Browse search box is controlled and URL-backed.** It searches as you type (400 ms pause), every filter change carries the text in the box, "Clear all" empties it, and back/forward restore both box and results. URLs are canonical (fixed parameter order) so the page can tell its own navigations from outside ones.
- **Search ranks:** names starting with the query → other real text matches (name, alt names, network, NULL-safe) → live before dead → trigram look-alikes. A–Z ignores leading symbols (`sort_name` in the view), so "&TV" files under T.
- **One `API_DATA_VERSION` (packages/shared) busts both caches.** The API keys Redis on it and the web sends it as `?v=` so Next's data cache (which survives restarts and deploys) can't serve responses from before an ordering or shape change. Bump it whenever either changes.
- **One site-wide player.** `<GlobalPlayer>` lives in the root layout and is positioned over the watch page's `<PlayerSlot>`; on other pages it docks as a mini player (bottom-right, close + expand). The `<video>` never unmounts, so browser picture-in-picture and playback continue across navigation. Shortcuts only apply on the watch page.
- **Live timeline.** When a stream keeps ≥ 30 s of history (its DVR window) the player shows a seek bar, time behind live, ±10 s buttons (also ←/→) and a LIVE button to jump back to the edge. Controls fade after 3 s of no input while playing and return on mouse, touch or keyboard input.
- **Home hero is a carousel** of the best live channel per category (news, entertainment, movies, sports, music, kids, documentary, religious; preferring channels with a logo) plus "Most watched now", via `GET /v1/channels?sort=best` (health score, then resolution). Rotates every 7 s; pauses on hover/focus, on request, and for reduced-motion users.
- **Home shows a rail for every category with ≥ 6 live channels** (30 rows today), ordered: entertainment, movies, sports, kids, music, news, series… then by size, shopping last; each rail lists its best channels first (`sort=best`). Rails use `content-visibility: auto` so off-screen rows cost little to render.
- **Google AdSense banners (owner decision, 2026-10-28)**, overriding the guide's "no ads until legal review". Placements: home (before the first category rail and every 6 rails), browse/category/search pages (under the grid), watch page (below the title). The owner also asked for ads over the video and in the mini player; not built, because AdSense display ads on or over video content violate its placement policy (video ads need Ad Manager/IMA and separate approval). Ads are off until `NEXT_PUBLIC_ADSENSE_CLIENT` is set; dev mode shows dashed placeholders. `/ads.txt` and the `google-adsense-account` meta tag are generated from the same setting. Known risks: AdSense prohibits sites that link to unauthorised copyrighted streams (pay-TV re-streams are listed in directory mode), and ads add cookies, so the AdSense consent message must be enabled for EU/UK visitors and the privacy policy must name Google as a processor.
- **Deploy target: Vercel (web) + Railway (API, worker, Postgres, Redis) + Cloudflare (domain, DNS)**, chosen by the owner; steps in `docs/deploy.md`. Railway Redis rather than Upstash: BullMQ polls Redis constantly, which per-request billing makes expensive.
- **Production bundles compile the workspace packages in.** `scripts/bundle.mjs` bundles `@tunely/*` (TypeScript source) into each app and keeps npm packages external; the previous `--packages=external` build could not start. API and worker images: two-stage Dockerfiles, production deps only, non-root. The API image carries the migrations and Railway runs `dist/migrate.js` before each deploy.
- **The worker imports the catalog on first start** when the channels table is empty.
- **ioredis uses `family: 0`** so it resolves IPv6 too (Railway's private network is IPv6-only). The API reads `PORT` (Railway) before `API_PORT`.
- **Free, always-on deployment: one Oracle Cloud Always Free ARM server running `deploy/docker-compose.yml`** (owner asked for $0 with no sleeping; managed free tiers either sleep or can't run the worker/queues). Caddy terminates HTTPS and serves the website and the API on one origin (`/v1/*` → API), so browsers need no CORS. A one-shot `migrate` service runs before api/worker; a `backup` service keeps 7 nightly `pg_dump`s. The web app builds as a Next.js standalone server (`output: 'standalone'`). Compose project name is `tunely-prod` so it can never touch the dev project's containers or volumes. Guide: `docs/deploy-free.md` (DuckDNS for a free domain; AdSense needs a real one).
- **No-card free deployment (owner has no card for Oracle): Vercel (web) + Render free (API and worker in one process) + Render free Key Value + Neon free Postgres + UptimeRobot pinger.** Render has no free background workers and one always-awake free service, so `deploy/render/start.mjs` runs migrations, then API and worker together; Render's pre-deploy step isn't free. The image caps the V8 heap at 320 MB: the catalog sync peaked at ~586 MB uncapped, and with the cap it completed inside a hard 512 MB container limit. The health checker's pace is now configurable (`HEALTH_BATCH_EVERY_MIN`, `HEALTH_BATCH_SIZE`, `RECHECK_AFTER_HOURS`, `HEALTH_SCORE_EVERY_MIN`, `CHECKS_RETENTION_DAYS`; defaults unchanged). `render.yaml` slows it (every 30 min, 2,000 per batch, recheck after 12 h, 7 days of history) so Neon's 100 compute-hours a month aren't exhausted by a database kept awake 24/7. Guide: `docs/deploy-free-nocard.md`.
- **Keep-awake endpoints for free hosting.** `/v1/health` stays dependency-free for cron pingers (cron-job.org/UptimeRobot); `/v1/health/details` adds Redis and a worker heartbeat (written to Redis every 60 s, stale after 3 min) and returns 503 when degraded. Neither touches Postgres, so pings don't wake Neon. All `/v1/health*` paths skip rate limiting.
- **`/v1/health/details` includes each worker job's last run** (time, duration, counts or error, plus a ':running' start time), stored in a Redis hash by the worker. It made a Render-only failure diagnosable without dashboard access.
- **Health-check catch-up mode.** After a catalog sync or a batch, if any stream has never been checked, the worker queues the next batch 5 s later instead of waiting for `HEALTH_BATCH_EVERY_MIN`. A fresh database goes live within ~30 minutes instead of ~4 hours; steady state is unchanged.
- **Channel lists revalidate every 5 minutes on the web** (was 30). Vercel's data cache had kept the empty lists served while a new database was filling, for up to half an hour. Country/category/language pages revalidate every 5 minutes; the facets-only Categories page stays at 30. `API_DATA_VERSION` → 5 to drop the stale entries.
- **Viewers can try any channel ("Try to play").** The channel API now returns every stream of a channel (verified first: web-playable with score ≥ 50); the player auto-plays only verified streams. When none work, or the channel is offline, the player offers "Try to play" with the remaining streams a browser can load (HTTPS, no referrer/user-agent headers). This covers streams our Singapore server can't reach but viewers can (country-limited, datacenter-blocked). Every attempt is reported.
- **Player-confirmed streams go live.** A stream that ≥ 2 distinct viewer sessions played OK in 24 h (with ≥ 50% of attempts succeeding) scores 60 and is marked web-playable even if our checks fail. The 10-second report flush re-scores just the reported streams and rebuilds the directory only when a status changed, so this takes about a minute. Known limit: reports are rate limited per IP but not authenticated, so a determined user could mark a channel live; at worst that lists a channel that may not play.
- **Browse history is deterministic.** The first search typed after another change adds a history entry, and further typing updates it; previously this depended on whether the previous page had finished loading (found by a 1-in-3 flaky e2e test).
- **Mobile navigation is a bottom tab bar** (under 720 px: Home, Live TV, Categories, Favorites) with a slim top header for the logo and theme. The separate Search tab is gone: it was the same page as Live TV. `/search?q=` permanently redirects to `/browse?q=` (next.config `redirects`). On phones the browse filters fold behind a "Filters" button.
- **Fullscreen locks phones to landscape** (`screen.orientation.lock`, Android Chrome). iPhones use the native video fullscreen, which rotates with the phone.
- **"Your device can't play this video" is its own error.** Some streams (e.g. Sun TV) are HEVC/HDR only, which plays only where the device has the decoder (Safari on Apple, many Android phones, Edge on Windows). hls.js codec errors are now `unsupported_codec` instead of "offline"; such reports don't lower the stream's score, since they say nothing about the stream. When hls.js fails with a codec or CORS error and the browser has native HLS, the player retries natively first.
- **AdSense readiness.** Added About, Privacy (with the disclosures AdSense requires: third-party cookies, opt-out links, consent for EEA/UK), Terms, Contact and Copyright/DMCA pages, linked from the footer and in the sitemap. Takedowns are by email for now; the form stays a later phase.
- **Generated text on every indexable page.** Watch pages get an "About this channel" paragraph and country/category/language pages an intro, both built from catalog data, so pages aren't just a player or a grid ("low-value content" is the most common AdSense rejection). The home page has a short intro and FAQ.
- **Ads only next to content.** No watch-page banner unless the channel is live, and no browse banner on an empty result.
- **Structured data.** `TelevisionChannel` and `BreadcrumbList` on watch pages, `WebSite` + `SearchAction` and `FAQPage` on home. JSON-LD escapes `<` because channel names come from iptv-org.
- **Search Console verification** through `NEXT_PUBLIC_GOOGLE_SITE_VERIFICATION`.
- **Revenue besides AdSense.** Adsterra banners fill the existing ad spots only while AdSense isn't configured. They're banner units only, each in its own iframe so the ad's globals (`atOptions`) and `document.write` stay out of our page, and only the size that fits the screen loads. The iframe needs `allow-same-origin`: in a real-browser test on the live domain Adsterra served nothing without it. The isolation is therefore no stronger than AdSense's in-page script. The script URL is configurable because Adsterra serves it from a different host per account. A Support link (`NEXT_PUBLIC_SUPPORT_URL`) appears in the footer and on About. A new `/watch-on-tv` how-to page carries Amazon device links and an optional VPN link framed around privacy, never around bypassing region blocks. Every link is env-driven, https-only and validated, and off by default.
- **"Popular in your country" without breaking the cache.** The home page stays one ISR page; rendering it per country would multiply its ~25 API calls by every visitor country and risk the API rate limit. Instead `/geo` returns the country Vercel already detects (`x-vercel-ip-country`, uncached, nothing stored), and the browser adds the row when the country isn't the featured one (India) and has at least 4 live channels.
- **Installable app.** The manifest now has PNG icons (192, 512, maskable), drawn with `next/og` so there's no image tooling dependency, plus an apple-touch-icon. Chrome reports no installability errors and needs no service worker. The Install button shows only when the browser offers installation (`beforeinstallprompt`), or as a "Share → Add to Home Screen" how-to on iPhone/iPad, and hides once Tunely is installed.
- **WhatsApp and Telegram share links** on watch pages, as plain links (no SDKs or trackers).
- **Browse dropdowns are searchable, A–Z, with live counts.** A new `GET /v1/facets` returns counts per country, category, language and status for the current filters and search. Each dimension is counted with every filter except its own (standard faceted search), so you can see what switching would give. The list and the counts share one `channelWhere()` builder, so they can't disagree. It returns ids and counts only; names come from the existing cached `/v1/countries` etc., which keep their count order for the home page. The dropdown is a small in-house combobox (same ARIA pattern as the Ctrl+K search) with no new dependency: names starting with the search come first, accents and case are ignored, and the selected value is always kept.
- **SEO audit fixes, phase 1 (30 Oct 2026, see the Tunely SEO Audit report).**
  - **Listing pages ship real links.** Before hydration the browse grid renders its first page as a plain CSS grid with the same column rule. The virtualizer needs the window, so it rendered nothing on the server, and country, category, language and Live TV pages had no `/watch/` links in their HTML. It switches to the virtualizer after mount with no layout shift (CLS 0 measured). The first row's logos load eagerly, since they're the LCP image.
  - **Thin facet pages stay out of search.** Country, category and language pages with fewer than 10 live channels (`INDEX_MIN_LIVE`) render `noindex, follow` and are left out of the sitemap, computed from `GET /v1/facets?status=live`. If counts can't load, pages stay indexable rather than all disappearing for the 5-minute cache window.
  - **Filtered Live TV URLs** (`/browse?…`) are `noindex, follow` in addition to the `/browse` canonical.
  - **Home** gets a canonical and a descriptive title. Its only `h1` is "Free live TV from around the world"; the hero's rotating channel name became an `h2` with no visual change.
- **Pages for what people actually search (30 Oct 2026).** Google autocomplete showed big "app", "{language} live TV channels list" and channel-name searches.
  - **`/app`** is an honest install page for the PWA (no APK, Play Store or offline claims) with `WebApplication` JSON-LD and no ratings. It's linked in the footer, which also puts it in the sitemap.
  - **Facet page titles** read "{Country/Language} Live TV Channels List: Watch Free Online". Descriptions carry the live count and the top languages, categories or countries, from the same `/v1/facets` request the page already makes, so Next dedupes it.
  - **The home page features the national Indian news brands** in a curated "Top Indian news channels" rail. They stream free on their own sites.
  - **`/v1/channels?ids=`** fetches a curated set in one request: server-side renders share the API's per-IP rate limit, so 12 detail calls per home render was too many.
- **Home page speed (30 Oct 2026).** Lighthouse showed LCP of 9–12 s on mobile.
  - **Hero text no longer animates in or remounts per slide.** It started at opacity 0 and each rotation created a new LCP candidate. The block now stays mounted and updates in place, and the desktop logo keeps its crossfade.
  - **hls.js is no longer preloaded at module load.** `GlobalPlayer` is in the root layout, so that downloaded 179 KB on every page. It now preloads on intent (pointer, focus or touch on a channel card or "Watch live"); direct watch-page visits still load it through `attachStream`.
  - **Carousel dots** have a 24 px minimum width for tap targets.
  - **Logo resizing with wsrv.nl was tested and rejected.** It fails on every i.imgur.com logo (imgur returns 429 to it, and each failure takes 0.5–2 s), and 69% of live channels' logos are on imgur. imgur's own thumbnail suffixes return JPEG, which loses transparency. Vercel's image optimizer has a monthly free limit that about 5,000 logos would likely exceed. So logos stay as they are until there's a resizer that can reach imgur.
- **Audit fixes (30 Oct 2026).**
  - **A sync that would keep under half of the stored channels, streams or blocklist rows is refused.** The run is marked failed and the data stays. Half is deliberately loose: normal churn is a few channels a day, and a broken file loses nearly everything. A smaller loss still goes through.
  - **Hidden and removed curation rows outlive their channel,** so a takedown holds when a channel leaves iptv-org and comes back. A renamed channel id still escapes it.
  - **The API's Redis connection fails fast** (`enableOfflineQueue: false`, `maxRetriesPerRequest: 1`), and the rate limiter uses `skipOnError`. In a Redis outage the API answers from Postgres in milliseconds, without its cache or rate limits. That trade is deliberate: a brief unlimited window beats every request hanging. `maxRetriesPerRequest: 1` alone isn't enough: the first request answered in 2 s and the next stalled past 15 s. Only the worker's connection needs `maxRetriesPerRequest: null`, which BullMQ requires for blocking calls. A Redis that stays connected but stops answering isn't covered; `commandTimeout` would do that if it ever happens.
  - **The Postgres pool has an error listener.** Without one, a connection dropped while idle crashes the process, which on Render means the API and worker together.
- **Home category rails load on scroll (30 Oct 2026).** The page had 33 rails and 5,300 elements, which cost phones several seconds. All rails stay, but only the first two category rails are built on the server. `LazyRail` keeps the heading and "See all" link in the HTML, reserves the rail's height, and fetches its channels from the browser when within 800 px of the viewport. Which rails exist comes from one `/v1/facets?status=live` call. Home HTML went from 912 KB to 179 KB, the initial DOM from 5,348 to about 1,135 elements, and server-side API calls per home render from about 43 to about 15. The home page now links to fewer channels directly; crawlers reach them through the category pages it links to.
